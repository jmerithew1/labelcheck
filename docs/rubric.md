# LabelCheck Requirements Rubric

Every requirement extracted from [brief.md](brief.md), tracked with evidence. Vocabulary: **MET** (with evidence), **PARTIAL**, **MISSING**, **N/A-documented**. A claim only moves to MET with a file, test, measured number, or URL attached — never on "code written."

Verification points: spec approval (done), post-build final gate (done), pre-submit audit loop (done 2026-08-11): round 1 — 5 independent auditor lanes (clean-clone build, core claims, live app, brief-coverage adversary, docs-drift), 0 blockers / 9 minors, all fixed; round 2 — 4 lanes re-verifying live production behavior + docs, 0 blockers / 3 doc-accuracy minors, all fixed; round 3 — scoped re-check of the round-2 fixes found 3 residual doc findings (stale claims duplicated in the generator and decisions log; an unbacked latency number), fixed; round 4 — final re-check of the round-3 fixes, clean (loop exit). **Ship-readiness sweep 2026-08-12** (4 lanes over the full feature set against production — API + error handling, batch UI, single-check UI, repo/docs): 3 blockers (native image-drag killed drag-to-pan; two stale doc counts) and 6 minors, all fixed and re-verified; the changes it covered are the 2026-08-12 additions (attention-only bold strip, undo, agent ruling, hover magnifier, honest row status, opt-in bold pass over 60 rows, distinct demo artwork).

Validated against **200 harvested real TTB COLA labels, 156 of them scored** ([real-labels.json](real-labels.json)), which found and fixed two real defects — missing spaces after "(1)" treated as a wording deviation, and transcription running past the statement into an adjacent declaration; live: word-swap label fails with deviation named
- **C8 — MET** `GOVERNMENT WARNING` ALL-CAPS check; title case = hard fail — same module + test; live: title-case sample fails with §16.22(a)(2) citation
- **C9 — MET for wording and ALL CAPS (deterministic); bold is confidence-gated** These are two different kinds of check, so they are stated separately rather than collapsed into one verdict. Word-for-word and ALL-CAPS are deterministic string comparisons over a transcription and may hard-fail. **Bold cannot be, so it never fails a label**: it auto-verifies only where pixel measurement and model advisory agree, and routes everything else to a human. Multi-signal gate (stroke width + ink density + size sanity + Sonnet judgment) validated in a 3-round spike loop at zero confident mistakes — but on only **14 auto-resolved validation decisions**, which by the rule of three is consistent with a true error rate as high as ~21%, so the scale re-score below is the load-bearing evidence, not the spike. Re-scored against 160 non-bold samples across 4 templates × 40 degradations: **3 silent misses (1.9%) worst-case through the shipped gate**, with 7 caught by measurement alone and 150 routed to a person. Worst-case because it assumes the model wrongly answers "bold" on all 160. All three leaks are `glare2`/`noise1` — degradation that physically thickens strokes, i.e. the predicted failure mode rather than a surprise. **1.9% is not zero**: the defensible claim is that a non-bold label is very unlikely to reach a green check, not that it cannot. The re-score harness imports the shipped gate directly ([bold-gate-rescore.mjs:33](../samples/tools/bold-gate-rescore.mjs:33)) instead of restating its thresholds — a local copy silently fell out of sync the moment the gate gained a resolution floor, and would have gone on reporting against a gate that no longer existed ([bold-gate-rescore.json](bold-gate-rescore.json)). Versus **47 of 160 (29%)** for the raw model advisory alone — both measured on the same 160 samples — the measurement is what makes the difference, and anything it cannot resolve shows amber, never a green check. (That 47/160 advisory baseline is computed from the non-bold rows of [robustness-matrix.json](robustness-matrix.json), the corpus carrying the raw server advisory — this line previously miscited the 104-row [bold-multisignal-r2.json](bold-multisignal-r2.json) tuning run, which contains no such figure.) confident-bold auto-resolves ("verified by measurement"), confident-not-bold escalates to Needs review, inconclusive keeps the human glance via the **Confirm bold** strip (crops grid, confirm/flag, CSV `bold_check` column incl. auto_verified/auto_flagged); live sample batch: a majority of bold-eligible rows auto-resolve and the rest go to a human glance — the exact split varies run to run because the stroke-weight signal is re-judged each time, and no run log is committed, so treat the observed "roughly 7 of 11" as an anecdote rather than evidence; gate logic unit-tested (`lib/compare/boldGate.ts`); the §16.22(a) **body-not-bold** rule is also checked now (advisory, routes to review — 215 tests)
- **C10 — MET** Fuzzy fields, case/punct = MATCH surfaced: `STONE'S THROW` = `Stone's Throw` — [lib/compare/fields.ts](../lib/compare/fields.ts) + test; live: batch case-diff rows land clean-with-note (case-diff label also downloadable for single check)

- **C14 — MET (measured under degradation)** Jenny's evasion tactics all countered — and tested for survival under 40 degradation conditions each ([robustness-matrix.json](robustness-matrix.json)): text-based evasions (word swap, word drop, punctuation drift, title-case prefix) are caught in **635 of 640 samples (99.2%)** — that denominator counts only the 16 text-defect labels, deliberately excluding the 4 bold-only labels, because crediting bold misses to a text-evasion score would inflate it. Overall violation catch across all 800 samples is **739 of 800 (92.4%)**; the gap is the bold advisory, see C9. Jenny's evasion tactics all countered — *different wording*: exact canonical comparison + character diff (C7); *smaller font*: extractor reports warning size relative to the label, surfaces an advisory even when text is exact ([lib/vision/contract.ts](../lib/vision/contract.ts) `warning_text_size`; physical mm/characters-per-inch documented as not machine-checkable from an image, [approach.md](approach.md) §limitations); *buried in tiny text*: full-label transcription + tri-state presence — a warning anywhere on the label is found or its absence/illegibility flagged

### Performance
- **P1 — MET at the median; the tail is over the bar and is not rounded away.** Current build, re-measured after the deskew shipped: **p50 4.06s, worst 5.32s** (n=6, [post-deskew-latency.json](post-deskew-latency.json)) — one run of six crossed ~5s, and n=6 undersamples the tail rather than characterising it. The defensible claim is that the *median* label answers in about four seconds, not that five is a ceiling. The earlier pre-deskew run ([measured-performance.json](measured-performance.json), 2026-08-11) read **p50 4.3s, worst 4.5s across n=6 successful runs** and is kept for history — note that one is also worst-of-successful: `scripts/measure.ts` excludes non-OK responses, and [approach.md](approach.md) §limitations 6 records a cold start at 9.3s, a warm worst at 9.6s, and one run that never returned inside 45s. The ~5s figure is a median, not a ceiling; warning-*failing* labels also answer in **~4.0s** (measured live) — their second confirming reading runs asynchronously via `/api/confirm` (measured 5.4s) and updates the warning row in place, so the false-rejection guard (U4) costs no waiting; batch rows keep the blocking pass (~8s/row, absorbed by the batch wall-clock) — raw timings in [measured-performance.json](measured-performance.json). **Out-of-sample check, 2026-08-13**: 10 real approved TTB labels from `samples/real` (not the bundled demo set) through `/api/check` on the shipped async path — **median 5.1s to the verdict on screen, max 5.6s**, 10/10 matching the corpus expectation. Four of the ten returned a provisional `fail_wording` that the background second reading downgraded to review, which is what the headline's new "Double-checking the government warning" state exists to report honestly
- **P2 — MET** Batch 200–300 first-class — batch review page: CSV+files dropzone, loud pairing, filters/search/pagination, detail panel, sample batch
- **P3 — MET, now through the real UI** 250-label batch, two independent runs on the deployed app. Server path: **135s, 250/250 ok, 0 rate-limited, 0 errors** ([measured-performance.json](measured-performance.json)) — but that harness posts to `/api/check` from node and skips everything the browser does per row, which an audit rightly flagged as an unevidenced gap in a first-class requirement. Closed by driving 250 files through the **batch UI itself** — client-side deskew per image, 250 object URLs, filename pairing, streaming table: **146.5s, 250/250 completed, 0 errors, 0 rate-limited, 0 pairing issues** ([batch-ui-250.json](batch-ui-250.json)). Two honest notes on that run: the wall-clock is an upper bound (the browser pane was not composited throughout, which throttles timers — the counts are fetch-driven and unaffected), and **all 250 rows landed in Needs review**, because past 60 rows the bold pass is opt-in and a row whose bold was never examined must not show a green tick. That is deliberate and documented, but it does mean the brief's headline 250-label case starts as "review everything" until the agent clicks *Check bold type*. **Re-measured 2026-08-13 after this round's UI changes** ([batch-72-optin.json](batch-72-optin.json)), because the 250-row evidence predates them: 72 labels (past the 60-row opt-in point) checked through the UI in **56.8s, 0 errors, 0 rate-limited, 0 pairing issues**; clicking *Check bold type* then resolved **39 of 56 eligible rows by measurement**, leaving 17 for a human glance, settling in ~107s. So the "review everything" start is one click from "review seventeen". **The full 250 was then re-run on the deployed app, 2026-08-14** ([batch-ui-250-postfix.json](batch-ui-250-postfix.json)): **250/250 completed, 0 errors, 0 rate-limited, 0 pairing issues**, 190 clean / 40 needs-review / 20 warning-failure, counts read from the exported report rather than the table so they are exact. The app reported 139.1s against the earlier run's 146.5s — both measured with the browser pane hidden, so both are active processing time rather than foregrounded wall clock, and they are recorded as approximate for that reason. Counts move while that pass runs — a row still being measured sits in Matched and re-files to Needs review if its measurement comes back inconclusive, so an early read at 10s showed 49 matched and was optimistic by 16 rows; the settled figures are the ones recorded.

### UX
- **U1 — MET** Non-technical 50+ usable — 3-click demo verified in browser: sample → rendered verdict (single) and sample batch → triage, zero downloads/instructions; UX cold-read at final gate
- **U2 — MET** Loud human-readable errors — type/size guards, refusal/timeout/429 copy ([lib/vision/extract.ts](../lib/vision/extract.ts) `failureMessage`), not-a-label card, CSV-format and pairing errors
- **U3 — MET** Triage 250 without drowning — count-carrying filter chips (All / Matched / Need review / Not required; a row still owing a bold glance counts under Need review, so a green tick always means finished), one-click **Need review** filter + search, master-detail table (row click opens the evidence panel with an Audit trail tab; flagged fields and the bold glance are decided in place on their own rows, exactly as on the single-check page, and the panel footer carries an **Accept label** / **Reject label** ruling that outranks machine triage; Review next steps through), **Download report** (CSV with `agent_review` and `bold_check` columns), refresh guard; verified in browser on sample batch
- **U4 — MET** Dave's "don't make my life harder" = false-rejection aversion, designed in — tri-state `unreadable` ≠ `missing` (glare → "check manually", never a fail); second-reading confirmation on warning failures, plus four gates added after large-scale measurement — deviation-agreement (two readings must agree *which* word differs), legibility (no word-for-word claim on text that could not be read), disputed-absence, and statement-boundary trimming — measured **42 false rejections across 1,360 synthetic degradations (7.5% of compliant samples)**, concentrated in tear/occlusion where the warning is physically destroyed ([robustness-matrix.json](robustness-matrix.json)); on **156 scored real approved TTB labels** the tool's own false-rejection rate is **4 of 156 (2.6%)** ([real-labels.json](real-labels.json), causes in [real-labels-causes.json](real-labels-causes.json)): all 40 `fail_missing` verdicts were verified correct by direct inspection on contact sheets — front, neck or EU-market labels carrying no US warning — recorded per-label in [samples/real/manifest.json](../samples/real/manifest.json) (`has_warning: false` + `excluded_reason`). Those 40 are therefore excluded from the scored set, which is why the denominator is 156 and not 196, and of the 22 remaining flags **18 are labels whose printed text genuinely departs from 27 CFR 16.21** — square brackets for parentheses, a period for a comma, a dropped "the" — confirmed by a second independent reading and spot-checked by eye. Only 4 are the tool reading the wrong region of a crowded label; verdict vocabulary surfaces, never auto-rejects; case/punct differences read "Match — formatting differs" ([approach.md](approach.md) §perception/verdict, [degraded-fidelity.json](degraded-fidelity.json))

## Soft requirements (writeup lines mandatory)
- **N1 — MET on the stretch goal as written; extended well past it** — the brief asks to "tolerate imperfect photos (weird angles, bad lighting, glare)". Scored on exactly those three: **544 images, 224 compliant, 516 safe (94.9%), ZERO false rejections** ([robustness-matrix.json](robustness-matrix.json)). The claim is robust to how "bad lighting" is read: refuse to count `shadow` as bad lighting and it is **still zero false rejections**, on 196 compliant samples. All **28** violations not caught inside these families are bold-only defects measured at the raw advisory layer (see C9 — the shipped gate sends those to amber); **text-based violations are caught 256 of 256, 100%**. Two honest qualifications. First, "MET" is an assessment against a rubric written here, and a stretch goal is not a status the brief confers. Second, and more substantive: these 544 are *simulated* optics — degradations applied to rendered labels. Genuine photographs of physical bottles appear only in the real COLA corpus (curved labels with paper texture, foil stamps shot at an angle with real shadow), and that corpus by construction contains **no degraded capture** — nobody submits a badly-shot photo to a regulator. So "tolerates the named distortions" is supported, and "validated on photographs taken under those distortions" is not; the two corpora cover different halves and the seam between them is the honest gap. Testing then went beyond the ask — occlusion, tearing, creasing, curvature, sensor noise, colour cast and heavy downscaling — and **every one of the 42 false rejections in the full matrix comes from those extra conditions**, none from the three the brief names. Full detail — **1,360 synthetic degradations** (34 scoreable labels × 40 conditions: blur, angle, rotation, low light, overexposure, JPEG, downscale, glare, shadow, crease, curvature, tear, occlusion, sensor noise, colour cast, combined): **1,257/1,360 safe (92.4%), 42 false rejections (7.5% of 560 compliant samples), 61 violations not caught (7.6% of 800 violation samples)** ([robustness-matrix.json](robustness-matrix.json)). False rejections concentrate in physical destruction — occlusion (20) and tear (18) — where part of the warning is genuinely gone. Of the 61 not caught, **56 are the bold advisory**; re-scored through the shipped stroke-width gate that number falls to **3 of 160 (1.9%)** ([bold-gate-rescore.json](bold-gate-rescore.json)) — the matrix reads the raw server advisory, a layer the UI never shows. Also measured against **200 harvested real TTB COLA labels, 156 of them scored** ([real-labels.json](real-labels.json)). The COLA corpus mixes flat print files with genuine photographs (curved labels on bottles, angled foil stamps with real shadow), so real optics are represented; what it structurally cannot contain is **degraded capture** — nobody submits a torn or obscured photo to a regulator, which is why the synthetic matrix carries that axis. Real photographs of *damaged* labels remain the honest gap — [approach.md](approach.md) §limitations item 4
